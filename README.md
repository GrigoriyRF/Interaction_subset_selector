# Interaction_subset_selector

Отбор комбинации факторов с учетом взаимодействий

Набор скриптов решает две связанные задачи:

1. делит уже подготовленную модельную таблицу на train, valid и независимые holdout-выборки;
2. подбирает компактный набор факторов для CatBoost, учитывая качество, переобучение и совместную работу факторов.

Актуальная версия селектора: 0.10.1.

Главное ограничение

prepare_selector_samples.py — это не очистка данных в обычном смысле. Скрипт:

• не заполняет пропуски;
• не меняет типы столбцов;
• не удаляет дубликаты;
• не кодирует категории;
• не удаляет факторы автоматически;
• не исправляет значения целевой переменной.

На вход должна поступать уже готовая к CatBoost модельная таблица. Блок подготовки выборок отвечает только за воспроизводимое разбиение данных, контроль пересечений и создание служебных конфигураций.

Требования

• Python 3.10 или новее;
• Parquet как рабочий формат выборок селектора;
• CatBoost;
• Polars;
• PyArrow;
• NumPy;
• scikit-learn;
• PyYAML.

Базовая установка:

```bash
python -m pip install \
  "catboost>=1.2.8" \
  "numpy>=1.26,<3" \
  "polars>=1.30" \
  "pyarrow>=16,<24" \
  "scikit-learn>=1.5" \
  pyyaml psutil
```

Для распределенного backend дополнительно нужен Ray:

```bash
python -m pip install "ray[default]>=2.40,<3"
```

Конфигурация по умолчанию использует GPU. Для нее нужны рабочие драйверы NVIDIA и сборка CatBoost с поддержкой GPU. Для запуска на CPU задайте:

```yaml
model_params:
  task_type: CPU
```

Требования к исходным данным

В таблице должны присутствовать:

• бинарная целевая переменная target;
• стабильный ключ для воспроизводимого разбиения и семплирования;
• идентификаторы сущностей, если требуется контролировать утечки между выборками;
• временной столбец, если используется temporal-разбиение;
• категориальные факторы уже в формате, который принимает CatBoost.

В каждой созданной выборке по умолчанию должны присутствовать оба класса таргета. Сумма долей train_fraction, valid_fraction, oos_fraction, oot_fraction и test_fraction должна быть равна 1.0.

Роли выборок:

• train — обучение моделей;
• valid — внутренний подбор комбинаций и подтверждение финалистов;
• oos — независимая проверка, которая может участвовать в выборе финального набора;
• oot — более поздний holdout, оценивается после выбора набора;
• test — дополнительный полностью замороженный holdout, также не участвует в выборе.

train и valid обязательны. Остальные роли необязательны.

Рекомендуемый порядок работы

1. Подготовить базовые выборки

Скопируйте пример конфига и заполните его:

```bash
cp config.sample-preprocessing.example.yaml config.sample-preprocessing.yaml
```

Минимально нужно проверить:

• input.path — путь к исходной таблице, директории Parquet или glob;
• input.target и input.positive_label;
• sampling_key_columns;
• leakage_key_columns и bootstrap_key_columns;
• split.mode, доли и временной столбец;
• output.directory.

Запуск:

```bash
python prepare_selector_samples.py \
  --config config.sample-preprocessing.yaml
```

Поддерживаемые режимы:

• stratified — воспроизводимое разбиение с учетом таргета;
• random — разбиение по стабильному ключу без стратификации;
• group — одна группа не попадает в разные выборки;
• temporal — выборки идут последовательно по времени;
• group_temporal — финальные периоды выделяются по времени, а группы из финальных holdout удаляются из истории;
• auto — выбирает режим по наличию time_column и групповых ключей.

При folds.enabled: true фолды строятся только из базовых train + valid. Данные oos, oot и test в фолды не попадают.

Результат в output.directory:

```text
split_parts/
├── train/
├── valid/
├── oos/                 # если настроен
├── oot/                 # если настроен
├── test/                # если настроен
├── folds/               # если folds.enabled: true
├── selector_data.yaml
├── folds_manifest.json  # если folds.enabled: true
└── split_manifest.json
```

selector_data.yaml содержит готовую секцию data для следующих этапов. split_manifest.json фиксирует параметры разбиения, статистики, контроль строк и пересечения групп.

2А. Обычный однократный отбор

Если stability selection не нужен, объедините секцию data из split_parts/selector_data.yaml с полным шаблоном config.interaction-selector.example.yaml. Сохраните результат, например, как config.run.yaml.

Сначала рекомендуется выполнить только предварительную проверку:

```bash
python interaction_subset_selector.py \
  --config config.run.yaml \
  --plan-only
```

Команда проверит схему, пути и доступные ресурсы, не начиная обучение. План будет записан в preflight_plan.json внутри выходной директории.

Полный запуск:

```bash
python interaction_subset_selector.py --config config.run.yaml
```

Альтернативный вариант — отредактировать блок CONFIG: EDIT ONLY THIS BLOCK в run_interaction_selector.py и выполнить:

```bash
python run_interaction_selector.py
```

Этот launcher сам берет полный YAML-шаблон из той же директории, подставляет проектные пути, определяет категориальные столбцы по Parquet-схеме, создает config.run.yaml, выполняет preflight и запускает селектор. Для одной только проверки ресурсов задайте в нем PLAN_ONLY = True.

2Б. Отбор с проверкой устойчивости

Этот путь использует фолды, созданные первым этапом.

Скопируйте и заполните конфиг:

```bash
cp config.stability-selection.example.yaml config.stability-selection.yaml
```

Укажите актуальные пути в параметрах:

• selector_script;
• selector_template_config;
• selector_data_config;
• folds_manifest;
• output_directory.

Первый запуск лучше делать с run_final: false:

```bash
python run_stability_selection.py \
  --config config.stability-selection.yaml
```

Runner выполняет селектор отдельно на каждом фолде. В этих запусках автоматически отключаются oos, oot, test, robust validation и подбор порога. Затем он считает:

• частоту выбора каждого фактора;
• устойчивое ядро stable_core;
• пул кандидатов для финального запуска;
• устойчивые пары факторов;
• Jaccard-сходство наборов между фолдами.

Основные результаты:

```text
stability_selection/
├── fold_configs/
├── fold_runs/
├── feature_stability.csv
├── pair_stability.csv
├── stability_report.json
└── config.final.yaml
```

После проверки отчета установите run_final: true и повторите команду. Финальный селектор будет запущен на базовых train/valid с исходными oos/oot/test; его результаты появятся в stability_selection/final_run/.

resume: true позволяет пропускать уже завершенные фолды, если их конфигурация не изменилась.

Как работает селектор

Селектор не ранжирует факторы по одному. Он оценивает полные подмножества и ищет сочетания, в которых факторы усиливают друг друга.

Основные стадии:

1. проверка входных схем, ролей выборок и ограничений;
2. построение внутренних screen, search и confirm семплов только из заданных train/valid;
3. дешевый поиск на малых семплах и successive halving;
4. исследование случайных подпространств;
5. многоцелевой эволюционный поиск по качеству, размеру набора и разрыву между train/valid;
6. учет устойчивых пар, троек и коалиций факторов;
7. локальные операции добавления, удаления и замены;
8. подтверждение финалистов на более крупных семплах и нескольких seed;
9. при наличии OOS — парное bootstrap-сравнение финалистов;
10. выбор рабочего порога и его замороженная оценка на OOT/test.

OOS может влиять на выбор победителя. OOT и test используются только для финальной оценки уже выбранного решения.

Основные настройки селектора

data

Пути к выборкам, таргет, служебные ключи, категориальные, исключенные и обязательные факторы. Служебные ключи и таргет не рассматриваются как факторы модели.

sample

Доли положительного и отрицательного класса для стадий screen, search, confirm и holdout. Уменьшение доли отрицательного класса ускоряет перебор; обучающая выборка при этом может получать поправочные веса.

search

Метрика, минимальный и максимальный размер набора, объем случайного и эволюционного поиска, successive halving, ограничения на train/valid gap и допустимое падение качества ради более компактного набора.

robust_validation

Bootstrap-проверка на OOS и финальная оценка на OOT/test. Если require_oos: true, путь oos_path обязателен.

decision_threshold

Выбор порога по ограничениям на recall и precision. Порог подбирается на confirm_valid, проверяется на OOS и после этого замораживается для OOT/test.

execution и resources

Параллельность, backend, таймауты, retry, checkpoint, лимиты CPU/RAM/GPU и автоматическое снижение конкурентности после нехватки памяти.

Для локального запуска наиболее безопасна комбинация:

```yaml
execution:
  backend: local
  local_trial_mode: process
  parallel_trials: 0
  threads_per_trial: 0

resources:
  enabled: true
  mode: auto
```

Значение 0 здесь означает автоматический безопасный расчет, а не отключение ресурсов.

Результаты основного селектора

Ключевые файлы выходной директории:

• selected_features.json — выбранные факторы, метрика, gap и результаты независимой проверки;
• pareto_confirmed.json — подтвержденные финалисты;
• pareto_search.json — Pareto-фронт стадии поиска;
• baseline.json — качество базового набора;
• interactions.json и synergy.json — найденные взаимодействия;
• coalitions.json — устойчивые коалиции факторов;
• threshold_validation.json — выбранный порог и его проверка;
• robust_oos.json — bootstrap-сравнение на OOS;
• selection_stability.json — устойчивость между рестартами;
• trials.jsonl и trial_diagnostics.jsonl — история испытаний и диагностика;
• run_manifest.json — версия, конфигурация, зависимости и fingerprint запуска;
• resource_plan.json, resource_usage.jsonl, resource_summary.json — план и фактическое использование ресурсов;
• search_state.json и каталог cache/ — продолжение прерванного поиска и повторное использование результатов.

Главный файл для дальнейшего моделирования — selected_features.json.

Проверки

Быстрый встроенный self-test алгоритма:

```bash
python interaction_subset_selector.py --self-test
```

Модульные тесты:

```bash
python -m unittest discover -p "test_*.py" -v
```

Полный E2E-тест создает синтетические Parquet-выборки, запускает весь селектор и проверяет кэш повторным запуском:

```bash
python e2e_interaction_subset_selector.py
```

Можно сохранить его рабочие файлы в указанной директории:

```bash
python e2e_interaction_subset_selector.py --workdir ./e2e_tmp
```

E2E выполняет реальное обучение CatBoost и поэтому заметно тяжелее модульных тестов.

Частые ошибки

Unknown ... config sections
В YAML есть неизвестная секция. Старое имя audit больше не поддерживается; используется validation.

Доли выборок не дают 1.0
Проверьте сумму всех пяти долей, включая нулевые oot_fraction и test_fraction.

Пересечение групп между выборками
Заполните leakage_key_columns/group_columns и используйте group либо group_temporal. Не выключайте проверку, пока причина пересечения не изучена.

Категориальный фактор не указан
Селектор не преобразует типы. Передайте полный список в categorical_features или используйте launcher, который определяет строковые, dictionary и boolean-столбцы по Parquet-схеме.

Выходная директория не пустая
Для подготовки выборок задайте новую директорию или осознанно включите output.overwrite: true. Не размещайте выходную директорию внутри директории исходных данных и наоборот.

Нехватка памяти
Оставьте автоматический расчет ресурсов, уменьшите search.max_features, объем поиска или доли отрицательного класса. Локальный режим process безопаснее thread, потому что отдельный упавший fit не завершает основной процесс.

GPU недоступен
Проверьте драйвер и CUDA либо переключите model_params.task_type на CPU.

Минимальная схема процесса

```text
готовая модельная таблица
        │
        ▼
prepare_selector_samples.py
        │
        ├── train + valid ──► обычный selector
        │
        ├── folds ─────────► stability selection ──► финальный selector
        │
        └── oos / oot / test ─────────────────────► независимая проверка
```

Для быстрого эксперимента достаточно обычного однократного запуска. Stability selection имеет смысл применять перед фиксацией набора факторов, когда важно убедиться, что результат не зависит от одного конкретного разбиения development-данных.
